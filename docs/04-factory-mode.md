# FACTORY 模式实验与恢复顺序

## 实验目标

FACTORY 模式的目的，是在不替换完整系统的情况下启用工程启动路径和 root ADB。
屏幕上的 `FACTORY mode` 只是用户界面提示；真正的工程状态来自启动链和内核
参数。未来可以单独隐藏提示，但不应为了隐藏文字而关闭工程状态。

## 已验证的思路

1. 完整备份当前活动槽的 ABL 与 `devinfo`。
2. 离线验证候选 Factory ABL 的格式、大小和兼容性。
3. 受限工具在连接设备后重新读取 GPT 和目标分区。
4. 要求目标仍为原始哈希，LUN 和长度仍与清单一致。
5. 先写候选 ABL，完整读回并校验。
6. 再写修改后的 `devinfo`，完整读回并校验。
7. 退出 9008，冷启动并检查 FACTORY 提示、ADB 与 root 身份。

真实镜像、哈希、扇区和确认口令不进入本仓库。

## 为什么必须读回校验

EDL 命令返回成功只表示传输流程没有报告错误，不代表目标内容完全正确。每次
写入后都要重新读取整个目标分区，并与预期 SHA-256 比较。只检查文件头或少量
扇区不足以证明写入完整。

## 恢复顺序

若配对修改 ABL 与 `devinfo` 后无法启动，恢复时优先恢复原始 `devinfo`，校验后
再恢复原始 ABL。每一步都必须完整读回。不要执行擦除，也不要顺手切换 A/B 槽。

本次实验曾通过恢复原始 `devinfo` 验证正常启动，随后才进行配对写入。这一恢复
演练很重要：未经验证的备份不能视为恢复方案。

## OTA 风险

进入 FACTORY 模式后不要直接接受 OTA。升级可能写入非活动槽、替换 ABL 或改变
`devinfo` 解释方式。升级前应重新备份 GPT 和所有启动关键分区，并准备恢复工具。
