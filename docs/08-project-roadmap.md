# 项目边界、架构与路线图

## 项目名称

- 正式名称：**Action5 Pro Lab**
- 建议仓库名：`action5pro-lab`
- 一句话说明：为 DJI Osmo Action 5 Pro 增加可恢复、可验证的 Linux 扩展能力。

名称不使用“通用相机”“DJI Action”或单纯的“Unlock”，因为项目既不支持其他
型号，目标也不止解锁启动链。

## 支持范围

唯一目标设备：

```text
DJI Osmo Action 5 Pro
产品代号：AC204
平台：QCS8550/SM8550 系列
```

明确不支持 Action 4、后续 Action 型号、Pocket 系列或其他 QCS8550 设备。文档
中提到的“设备”“相机”和“Action5 Pro”均指 AC204，除非章节另有说明。

## 计划中的模块

### 1. 启动与恢复

- 9008/EDL 只读探测和备份；
- A/B 槽判断；
- FACTORY 模式维护；
- 写前检查、写后读回及一键恢复清单。

### 2. `action5d` 后台服务

计划使用一个轻量 ARM64 Linux 守护进程统一管理状态，避免多个脚本同时操作
Wi-Fi、存储和转码器。它应读取充电、温度、拍摄、存储和网络状态，并通过
systemd 启动。

### 3. 家庭网络

- 保存家庭 Wi-Fi 配置；
- 在不影响 DJI Mimo 热点模式时切换 STA/AP；
- DHCP、重连和网络可达性检测；
- 默认关闭或限制 root ADB 的网络访问。

### 4. NAS 同步

- 识别新照片和视频；
- 先写临时文件，校验完成后原子改名；
- 支持断点续传、重复检测和失败重试；
- 记录本地同步状态，但不删除原片；
- NAS 不可达时不影响相机拍摄。

具体传输协议将在 SMB、NFS、SFTP、rsync/rclone 类方案中根据设备资源和可靠性
测试选择，不预先绑定某一种实现。

### 5. 充电时转码

只有同时满足“外部供电、未拍摄、温度安全、剩余空间和内存足够”才运行。
采用流式处理和有界队列，优先研究平台硬件编码器；输出校验成功后再同步到
NAS，原始素材默认保留。

### 6. 设置与交互

按风险从低到高推进：

1. 配置文件和命令行；
2. 相机本地网页设置页；
3. 独立 Wayland 页面或悬浮入口；
4. 研究 DJI 原生设置菜单的资源与 IPC，再决定是否嵌入。

核心同步服务不得依赖 GUI 补丁才能运行。原生设置集成失败时，后台功能和恢复
路径仍应可用。

## 设计原则

- 拍摄优先：录像或相机服务繁忙时立即让出 CPU、内存、存储和网络资源。
- 默认可恢复：A/B 另一槽和原始分区备份保持不动。
- 默认不删除：同步与转码成功不等于可以自动删除原片。
- 可重复执行：断电、掉网、重启后不会产生半文件或重复任务。
- 凭据隔离：Wi-Fi、NAS 密钥不进入 Git、日志或固件镜像。
- 版本绑定：任何二进制补丁必须明确绑定 AC204 固件版本并支持校验失败时拒绝执行。

## 里程碑

1. 完成启动链、恢复和硬件基线文档。
2. 建立安全的应用部署目录和 systemd 服务骨架。
3. 稳定连接家庭 Wi-Fi，同时保留 DJI Mimo 使用路径。
4. 完成只上传不删除的 NAS 同步原型。
5. 增加充电、温度和空闲条件判断。
6. 验证硬件/软件转码并建立资源上限。
7. 提供本机网页配置页。
8. 最后研究原生设置菜单入口和 FACTORY 字样隐藏。
