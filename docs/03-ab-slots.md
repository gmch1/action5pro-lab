# A/B 槽的判断方法

## A/B 的含义

A/B 不是两个可见的“系统选项”，而是两套关键启动分区，例如：

```text
xbl_a / xbl_b
abl_a / abl_b
boot_a / boot_b
system_a / system_b
```

启动链选择其中一套。OTA 通常写入非活动槽，验证后再切换。实验时保留另一槽
原样，可以增加恢复机会，但它不能替代完整备份。

## 判断时使用多条证据

### 1. EDL/GPT 属性

在 9008 中读取 GPT，检查成对分区的 A/B 属性。工具可对 EDL 输出中的
`Active True/False` 做尽力解析。不要只因为某个分区名带 `_b` 就认定 B 活动。

### 2. 已启动系统的内核命令行

系统能启动时执行：

```bash
adb shell cat /proc/cmdline
```

关注槽后缀字段，例如：

```text
SLOT_SUFFIX=_b
```

同时记录根文件系统设备，但不要单凭 `/dev/sdX` 编号判断槽位，因为设备编号
可能随布局变化。

### 3. 启动分区的一致性

`xbl`、`abl`、`boot`、`system` 应当指向同一个槽。若 GPT 属性、命令行和实际
挂载结果不一致，应停止写入，先弄清 bootloader 的选择逻辑。

## 本次实机观察

本次实验中，GPT/启动信息、内核命令行和根文件系统均指向 B，因此只修改 B
侧目标并保持 A 原样。这个结论只描述当时的那台设备和那次启动状态。

## 不建议主动切槽

在没有验证另一槽所有关键分区能配套启动之前，不运行 `setactiveslot`。切槽并不
等于恢复；旧槽可能来自另一固件版本，或从未完成一次可启动更新。
